我把一个「AI 埋点 Agent」开源了。

项目叫：SmartTrack。

它能根据：

* 历史埋点表
* 新需求文档
* （可选）需求截图

自动生成：

* 新的 Tracking Excel
* 事件说明文档
* 字段规则模板

本质上，它是一个：

专门服务产品 / 数据 / 研发协作的 AI Agent。

---

做这个项目的原因特别真实。

因为我发现：

大部分团队做埋点，其实都在重复劳动。

每次新功能上线：

产品写需求 → 数据补埋点 → 研发确认字段 → 大家开会对齐口径。

然后：

字段命名不统一、
事件触发理解不一致、
历史规范没人记得、
最后埋点越来越脏。

尤其团队规模一大。

“埋点”会慢慢变成一种组织负债。

---

所以我一直在想：

能不能做一个 AI Agent，

专门负责：

“学习团队历史埋点规范，然后自动延续它。”

于是有了 SmartTrack。

---

它不是简单的 prompt 拼接。

而是完整 Agent Workflow。

整个流程大概是：

1. 解析需求文档
2. 分析历史埋点结构
3. 提取规则模板
4. 自动推断新事件
5. 生成 tracking 文件
6. 输出事件说明文档
7. 保存运行摘要

底层是一个 graph workflow。

每个节点都负责不同能力。

包括：

* 历史规范学习
* 事件推断
* 字段继承
* 枚举分析
* 文档生成
* 结果校验

我自己特别喜欢这种：

“AI 不只是聊天，而是真正执行工作流”的方向。

---

我觉得 Agent 最有价值的地方其实不是：

“像人一样聊天”。

而是：

理解上下文之后，
持续执行复杂协作流程。

埋点刚好特别适合。

因为它天然就是：

* 多角色协作
* 规则继承
* 文档生成
* 结构化输出

而且非常重复。

---

SmartTrack 现在支持：

### 历史埋点学习

自动分析：

* event 命名
* property 结构
* block 样式
* 常见字段组合
* 枚举约束

很多团队的问题不是不会写埋点。

而是：

没人知道以前怎么写。

---

### 自动生成 Tracking Excel

输入 requirement.md。

它会自动生成：

new_tracking_file.xlsx

能直接给：

* 产品
* 数据
* 客户端
* 服务端

一起 review。

---

### 自动输出事件文档

除了 Excel。

还会生成：

tracking_event_doc.md

包括：

* 事件含义
* 触发时机
* 字段说明
* 数据口径

这个在真实团队里其实特别重要。

因为真正耗时间的不是“写埋点”。

而是：

反复解释埋点。

---

### 支持 Vision

可以额外输入：

需求截图。

Agent 会结合页面 UI 一起理解业务流程。

这一点非常像真实产品协作。

---

目前项目已经开源。

技术栈：

* Python
* Graph Workflow
* OpenAI API
* Vision Model
* CSV/XLSX Processing

支持：

* 交互确认模式
* 批量自动模式
* 模板继承
* 自动规则生成

---

我现在越来越相信：

AI + Workflow + Structured Output

会比单纯 ChatBot 更有价值。

尤其在：

产品协作、
数据治理、
研发流程、
内部工具

这些场景里。

因为企业真正缺的不是“聊天”。

而是：

能持续干活的 Agent。
